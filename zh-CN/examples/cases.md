# 案例：规则在真实场景里长什么样

10 个**完全虚构**的案例（人物、公司、数字都是编的）。每个案例的结构来自一次真实求职里真正发生过的问题，只是换了行业。每个案例标了它演示的规则。

| 案例 | 演示的规则 | 行业 |
|---|---|---|
| E1 | D-002、D-011 | 医院运营 → 医疗器械 |
| E2 | D-012 | 建筑设计事务所 |
| E3 | D-003、D-013 | 教材出版 |
| E4 | D-003、D-013、D-014 | 体育赛事 |
| E5 | D-004 | 连锁零售 → SaaS |
| E6 | D-002、L-12 | 物流 |
| E7 | D-014（计划与成果） | 管理咨询 → 企业战略 |
| E8 | D-014（贡献之间的关系） | 非营利组织 |
| E9 | D-015 | 酒店收益管理 + 副业 |
| E10 | D-016 | 快消 → 电商平台 |

## E1　医院运营主管 → 医疗器械 Market Access Manager

候选人曾牵头重新设计区域转诊路径，并说服 4 家合作医院采用。模型不熟悉「转诊路径设计」，把它改写成了最安全的通用说法。

- ✗ 第二版：负责与区域合作医院的关系维护
- ✓ 修正后：设计区域转诊路径方案，推动 4 家合作医院采用，平均转诊等待时间缩短 30%

要点：降级后的版本在关键词上和 JD 更接近，却丢掉了唯一能证明「说服机构改变做法」的证据，而这正是 Market Access 的核心。

## E2　建筑设计事务所项目经理

一段经历里有两种能力：投标阶段通过业主访谈重新界定项目范围，赢得 HK$8M 设计合同；中标后统筹 6 家分包单位按期交付。

- 投「业务拓展经理」：通过业主需求访谈重新界定项目范围，提出差异化方案，赢得 HK$8M 设计合同
- 投「工程项目经理」：统筹 6 家分包单位与业主方，在 14 个月内按期交付
- ✗ 混写：负责项目从投标到交付的全流程管理

要点：两个版本的事实完全一致，只是选择和顺序不同。混写版本两边都不够强。

## E3　出版社教材项目经理 → 运营岗

候选人是一套教材的项目负责人，内容由作者团队撰写，插图由外部团队完成。出版社内部估算这个系列的潜在市场约 5 亿元。

- ✗ 第一版：主导打造一套教材系列，开拓 5 亿元市场
- ✓ 修正后：作为项目负责人统筹 12 位作者与外部插画团队，按期交付 3 册教材，首年进入 40 所学校

要点：「主导打造」把创作的功劳算到了项目经理身上；「开拓 5 亿市场」把潜在规模写成了成果。真正能迁移到运营岗的是多方协调和按期交付。一个数字要靠很长的限定语才能说清时，换一个本身没有歧义的数字更好。

## E4　体育赛事公司 Event Coordinator → 品牌合作 / BD

职位是协调岗，候选人第一轮也只描述了现场执行。追问「你参与过哪些和钱有关的决定」之后，得知她设计过赞助权益方案并参与谈判，还负责每周跨部门复盘。

- ✗ 按职位名称写：协调赛事现场执行与供应商
- ✓ 追问后：设计三档赞助权益方案并参与谈判，促成 HK$1.5M 赞助合同；建立每周跨部门复盘与数据看板

要点：「参与谈判」不能写成「谈下」。金额前的动词决定归属，金额后的类别（现金、实物、潜在）决定性质，两者都不能丢。

## E5　连锁零售门店运营经理 → SaaS Customer Success Manager

候选人没有 SaaS 供应商一侧的经验，但主导过新 POS 系统在 35 家门店上线。

- ✗ 替换术语：推动 SaaS 产品客户采用率，降低客户流失
- ✓ 相邻能力：主导新 POS 系统在 35 家门店上线，组织店员培训并跟踪使用数据，3 个月内日常使用率从 40% 提升到 85%

要点：替换术语的版本，面试官第一个追问就会露馅。写相邻能力的版本，让招聘经理自己得出「她懂用户采用」的结论。

## E6　物流公司候选人的四轮迭代

演示语义回退如何发生、如何被拦下。

1. v1：候选人确认「重新设计华南区配送网络，单票成本下降 18%」，写进 Claim Card 并标为 `protected`
2. v2：针对另一个 JD 调整摘要，这一条保持不变
3. v3：模型为了「更贴合 JD」，把它改成「参与优化区域物流流程」。Claim ID 还在，`check_claims.py` 通过了；自审时逐句对比已批准措辞，发现强动词和数字都没了，拦下
4. v4：恢复原措辞，Change Log 里写明「本轮只改摘要与技能顺序」

## E7　管理咨询分析师 → 企业战略岗

候选人把一段经历写成「为客户准备了渠道拓展提案（未落地）」。追问「提案里有没有哪一部分后来被用上了」，得知其中的经销商分级标准被客户采纳，用于下一年度的经销商评估。

- ✗ 直接排除：只是提案，不进简历
- ✗ 夸大：主导客户渠道拓展
- ✓ 追问后：设计经销商分级标准，被客户采纳用于年度经销商评估

要点：提案整体没有落地，但其中一部分被执行了。只有追问才能发现。

## E8　非营利组织项目官员

候选人写过一份社区独居老人需求调研报告；之后一家基金会新设了上门探访项目。

- ✗ 写成因果：调研报告促成基金会设立新项目
- ✗ 一律拆开：两件事分别写，不提关系
- ✓ 追问后：得知报告被基金会的项目评审会引用为立项依据之一。写法：撰写的需求调研报告被列为基金会上门探访项目的立项依据之一

要点：先问清楚连接是什么，再决定怎么写。「依据之一」既写出了价值，也没有把功劳全算到自己身上。

## E9　酒店收益经理，兼职联合创办咖啡店

候选人全职做酒店收益管理时，和朋友联合创办了一家咖啡店，自己负责定价和菜单毛利设计，日常经营由合伙人负责。

- ✗ 模糊：Entrepreneur, F&B ventures
- ✗ 写成免责声明：联合创办一家咖啡店（非全职，仅周末参与，日常由合伙人经营，本人不参与管理）
- ✓ 最强且站得住：Co-founder（2021–2023，与全职工作并行），负责定价与菜单毛利设计，开业首年实现盈亏平衡

要点：第二种和第三种都准确。区别在于篇幅花在哪里：第二种花在解释自己没做什么，第三种花在证明自己做了什么。

## E10　快消经销商经理 → 电商平台商家增长经理

JD 要求「数据驱动，精通 SQL」。候选人有 6 年经销商管理经验，SQL 只会基础。看了这家公司同类岗位在职者的公开履历后发现，多数人来自商家运营和销售背景，数据能力是加分项。

- 调整：经销商管理放在第一位，SQL 如实写成「能用 SQL 做基础分析」
- ✗ 反面：为了贴 JD 把 SQL 写成「精通」，或者因为不精通就放弃申请

要点：调研改变了经历的排序和要不要投，没有改变事实。
