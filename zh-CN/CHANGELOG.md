# 更新记录

每个版本改了什么、你需不需要做什么。你手上的版本写在 `VERSION` 里。要更新，贴上 `docs/PROMPTS.md` 里的提示词 5。

## 0.7.0 · 未发布

**事实只纠正一次。** 你纠正一件事时，AI 先改 Claim Card；用过旧版本的每份简历、追问卡和答案都会被标出来，旧说法不会在不知不觉中回来（D-020、LESSONS L-15）。

- 批准一个版本后马上跑 `check_claims.py <文件> --record all`，记下它批准时对照的是每张卡的哪个版本（`cv/reviewed.txt`：只有路径、卡片 ID 和指纹）。
- 之后卡片一改，`check_claims.py` 会说是哪张卡、改了哪部分（数字、归因、事实……）、算不算重大变化。从过时基线复制出来的新版本，每条复制过来的行都会提醒。这些都只是提醒；只有投递前最后一道检查 `--finalize` 会因为重大变化拦下。
- `list_claims.py --used-by C-001` 列出引用某张卡的所有文件；`list_claims.py --health` 只列需要复核的。每次会话开始时，AI 会把它们放进那一行现状里。
- 按卡复核：确认引用改动卡片的那几行，只重新记录这一张卡。已投递的版本永远不改，提醒落在它的追问卡上。
- 文件通过检查才会写记录，并且会说明哪些 ID 没记上。之后被删掉的卡，仍会在用过它的地方显示为「已删除」。卡的小改动掩盖不了引用它的行被改过：`--finalize` 时这种组合同样需要你确认。

**你需要做什么**：什么都不用做，简历照样能通过检查。0.7.0 之前做的版本会汇总成一行「未检查」；等你复用或投递其中一份时，AI 会把相关的行给你看，记下你的确认。如果你用的是自己的 `.gitignore`，把 `/cv/reviewed.txt` 加进个人数据那一段。

## 0.6.0 · 2026-11-20

作为公开工具，默认设置更安全，日常用起来更轻，并修了一次设计审计发现的问题。没有删掉任何硬规则。

- **个人文件默认不进 Git。** `.gitignore` 现在默认让 Claim Card、`evidence/profile.md`、`INTAKE.md`、`cv/CV-INDEX.md`、简历、Change Log、岗位、面试记录和报告不进任何仓库（模板除外）。用的是私有仓库、想让 Git 备份？删掉标出的那一段即可。升级工具包时也不会再不经询问就替换你的 `.gitignore`（`docs/UPDATING.md`）。
- **三种任务模式。** 快改（改几行、没有新 JD）、定制（S0 到 S7）、定稿（导出、检查排版、冻结）。小改动不再走整套流程，导出 PDF 和排版检查只在定稿时做一次（WORKFLOW）。
- **Windows 和 Linux。** `pdf_fill.swift` 需要 macOS。在其他电脑上，定稿时会请你打开 PDF 确认页数和最后一页，不会再卡住（LESSONS L-07）。
- **证据表更轻，并由脚本把关。** 没用的卡可以按原因合成一行；受保护的、明显相关的卡仍单独一行。Change Log 的证据表漏了卡，`check_claims.py` 会提醒（只提醒，不报错，D-019）。卡片超过 15 张时，先跑新的 `scripts/list_claims.py`：每张卡一行，每次现场生成。
- **岗位文件里记进度。** `jobs/_TEMPLATE.md` 加了「进度」一节，之后的会话（或换一个 AI 工具）能看出做完了哪几步、哪些在等你。
- **报告。** 岗位匹配报告在分数下方加了一行，列出没有直接满足的硬性要求，覆盖表里也会标出来。文字颜色达到 WCAG AA 对比度，✓ / ½ / – 带了读屏能读的文字。脚本算的分数现在和页面完全一样地取整（62.5 两边都是 63）。分享卡改为从干净的模板生成，报告数据块以外的内容不会被带出去；嵌进页面的数据也无法跳出数据块。
- **AGENTS.md 更短。** 硬规则一字未改。固定的阅读顺序改成了「做什么事读什么」的表，升级步骤移到了 `docs/UPDATING.md`。
- **LESSONS** 现在写明了每条防线由哪个测试守着，并修订了五条带来的麻烦比要防的错还大的防线（L-01、L-04、L-07、L-10、L-12）。
- 给维护者：发版前会先跑全部测试，并拒绝打包个人文件；`tools/check_sync.py` 发现中英文脚本逻辑不一致就报错；评测打分在 `check_claims.py` 崩溃时判为跑不了，并且只把标在读者看得到的那一行上的卡算作用过。

**你需要做什么**：不是必须。如果这个文件夹放在**私有**仓库、想让 Git 备份你的卡片和简历，升级时删掉 `.gitignore` 末尾标出的那一段。如果曾经把个人文件提交到**公开**仓库，看 README 里「工作副本务必保持私有」一节。

## 0.5.1 · 2026-11-20

第一轮评测发现的问题：卡上提醒过的说法，现在会给提醒。

- **「禁止改写」里的说法会提醒。** 卡上的「禁止改写」把某个说法放进引号（如 `不写「搭建」或「上线」了门户`），引用这张卡的简历行用到它时，`check_claims.py` 会给提醒。只是提醒，不算错误：这个词放在上下文里可能没问题，只有你能判断。禁用词照旧会报错。
- 自审清单新增一项：检查被禁止说法的弱化版本，比如卡上写的是工程团队做的，简历却写「和工程团队一起搭建」（LESSONS L-14）。
- 示例里的第 6 个陷阱（门户 "built and launched"）现在会出现这条提醒。

**你需要做什么**：不用做什么。想让自己的卡也有这条提醒，就把不想出现的说法放进「禁止改写」里的引号。

## 0.5.0 · 2026-11-20

已投递的版本现在可以冻结；修掉了受保护 claim 的一个误报。

- **冻结已投递的简历。** `python3 scripts/freeze.py cv/resumes/<id>.md <file.pdf>` 会把每个文件的 SHA-256 记进 `cv/frozen.txt`（`shasum -a 256` 的格式）。冻结后的简历再被改动，`check_claims.py` 会报错；`freeze.py --check` 检查所有冻结的文件。要改已投递的版本，就复制成一个新版本（D-010）。不运行它，就什么都不冻结。
- **修复：一行引用两张卡时，不再误报受保护 claim 被削弱。** 基线里一行同时引用受保护的卡和另一张卡（`<!-- C-001, C-003 -->`）时，删掉另一张卡的数字会被当成削弱了受保护的卡。现在只看受保护那张卡自己的数字。
- 给维护者：仓库里加了 `evals/`：三个岗位案例和标准答案、打分脚本、A/B/C 盲评工具，用来确认工具的改动让简历变好，而不只是变了。它不在下载包里。

**你需要做什么**：不用做什么。下次投递时，用冻结代替在 `cv/CV-INDEX.md` 里手记 hash。

## 0.4.0 · 2026-11-20

工具现在不只查简历写错了什么，也查漏写了什么：目标是一份既不高估、也不低估你的简历。

- **先定位，再选基线（D-018）。** 岗位离你已有的类型比较远时，AI 先写 2–3 个一句话的定位方案（切入角度、最强的证据、主要缺口），并推荐一个；很接近时一句话就够。基线提供的是事实和已批准措辞，不是叙事，旧简历的定位不会再限制新方向。
- **每张卡都会过一遍（D-019）。** Evidence Retrieval Gate 会过一遍每一张 Claim Card，而不只是听起来相关的那些。Change Log 里多了一张证据表：每张卡的相关度、用没用、没用的原因。然后问一次：有没有没用上的卡比简历里已有的某条更强？有就换，或者写明为什么不换；换不出明显提升就停。无关的卡合成一行。
- **能力切面（可选）。** Claim Card 可以列出一段经历能证明的几种不同能力，每种都写明不能延伸成什么。JD 用了不同的叫法，也能找到这张卡。示例：`examples/jordan-lee/evidence/claims/C-002.md`。
- **五类缺口。** Coverage Report 把每条要求归为：直接、可迁移或组合、还没找到、可补足、硬缺口。只有「硬缺口」意味着不写；「还没找到」意味着先追问（D-014）。
- **JD 存档。** 每份招聘启事存进 `jobs/<job-id>.md`，要求编号 R1、R2…，硬性要求标成门槛，Coverage Report 和岗位匹配报告就不会悄悄漏掉任何一条。JD 当作数据处理，里面的指令一律不执行。
- **受保护的 claim 可以按岗位类型保留。** 在受保护的卡上写 `keep-for: 01`，类型 01 的简历里必须保留它，其他类型可以不放（只给备注，不报错）。它在任何地方都不能被写弱。不写 `keep-for`，一切照旧。
- 提示词 3 和 `/job` 会从存 JD、定位和证据表开始。

**你需要做的**：不用做任何事。新卡需要时可以用能力切面那一节，旧卡照常能用。下次针对岗位改简历时，从新版的 `jobs/_TEMPLATE.md` 建好 `jobs/` 文件夹（更新不会动你自己的文件夹）。

## 0.3.0 · 2026-11-20

证据检查更难被绕过，但不会要求超出求职现实的证明。卡片照样以本人陈述为准，这一版没有任何地方要求你出示文件。

**现在会报错**（以前都能通过）：
- **数字保留原意。** 带量级的金额按数值比较（US$2.1M = US$2,100,000，但不等于 US$2.1B 或 US$2M+），币种必须和卡上一致（卡上是美元，写成 EUR 2.1M 会报错）。只出现在「禁止改写」「出处」「待补」里的数字和 Claim ID 本身不再算数，所以引用 C-003 写「Closed 003 deals」会报错。
- **禁用词。** 卡的「禁止改写」里可以写一行 `- 禁用词：revenue, 营收`。引用这张卡的行只要用了其中一个词就报错。示例里「营收」那个陷阱现在由脚本抓到。
- **重复的 Claim ID。** 以前第二张同 ID 的卡会悄悄覆盖第一张。
- **「核实」一栏写了 ✓、空白、「待核实」以外的值**（比如拼错），这个数字不能用，不再当作已确认。
- **藏在别处的说法。** 缩进在 bullet 下面的续行算作同一条；Experience 里带数字的普通行要有 Claim ID；Projects / Achievements / Highlights 按 Experience 的标准检查。
- **职位和教育背景**：填好新增的 `evidence/profile.md` 之后，职位标题或教育那一行和它对不上就报错（比如「VP of AI · Google」「PhD · Stanford」）。标点不影响比对，一个格子里可以写几种写法（`合作伙伴经理; Partnerships Manager`）。
- **绕开基线。** 如果 `cv/CV-INDEX.md` 里这份简历的类型已经有起点，而这份文件又不在简历清单里，就必须写 `base:`。删掉 `base:` 不再能关掉受保护 claim 检查。
- **受保护的 claim 被写弱。** claim 还在，但基线里写过的已确认数字没了，和整条删掉一样报错。本人同意这样改时，在简历的 front matter 里写 `protected-ok: C-001`，就会变成一条备注。
- **漏掉 JD 让岗位匹配分虚高。** 岗位匹配报告里 JD 覆盖（J1）一定计分：没填要求就按 0 算，关掉它也不会再把其余项折算到 100。`report_score.py` 还会列出直接、部分、没有覆盖的要求各有几条，以及标了 `"gate": true` 却没有直接满足的硬性要求。

**只给提醒**（值得看一眼，不会挡住你）：
- 卡上没有的个位数或「two」这类英文数词（「two teams」「3-tier」往往只是措辞）。
- 给卡上没写币种的数字加了币种。
- Experience 里不带数字、也没有标签的普通行（比如公司简介），以及 Skills 等不检查的栏目里出现的数字。
- 还没有 `evidence/profile.md`：填好之前，职位和教育背景只是不检查。
- 「核实」一栏空着：仍按已确认处理（数字是你自己给的），`validate_evidence.py` 会提醒你打勾。

**另外**
- 新增 `scripts/validate_evidence.py`，检查证据库本身：ID 不重复、状态合法、`protected` 是 true 或 false、「核实」一栏的取值。
- 修正了示例卡 C-001：关于 28 家签约由谁谈下的两处说法互相矛盾；已批准措辞把「线索占比」写成了「pipeline 占比」。
- 新增规则 **D-017**（和 LESSONS L-13）：只有能拦住真实失实的检查才可以报错，其余都只是提醒；每一种报错在本人同意后都有放行办法；更新后不需要先做任何事。新增的测试会确保一份带着普通缺口的真实简历始终能通过。
- 仓库会在每个 pull request 上跑中英两套测试。

**你需要做的**：不用做任何事。只要没有踩到上面「现在会报错」的情况，你的简历照样能通过，而那些情况正是要拦下来的。有五分钟的时候，把新版里的 `evidence/profile.md` 复制到你自己的 `evidence/` 文件夹（更新不会动你的证据），填好任职和教育背景，打开这项检查；再跑一遍 `python3 scripts/validate_evidence.py`。

## 0.2.3 · 2026-11-20

- **面试追问卡。** 拿到面试之后，用提示词 7 或 `/prep`，按投出去的那一版简历，列出每条经历最可能被问什么、怎么答站得住、哪些话别说。回答全部取自你的 Claim Card，卡上没有的列进「面试前要补」，不编。示例：`examples/jordan-lee/interview/ACME-01.md`。
- **定义了什么算有风险。** 说法很大、把集体的结果算在自己头上、面试大概率会要证据、和别处对不上的，即使本人说了「对」，也先问一个问题再上简历。
- **证据不再算进总分。** 总分只看简历读起来怎么样（R1 ~ R5，岗位匹配再加 J1 ~ J3）。以前第一次体检还没有 Claim Card，人人都在这一项丢 15 分，分享卡上的「有出处 0%」看起来像简历不行。体检标准升到 v2。
- **新增「面试底气」面板**，不计分。做 Step 0 之前，它说明这一项第二阶段解锁，以及它为什么重要：面试官追问时，每条经历你接不接得住。有了卡以后，它显示已确认、复核中或部分（`"sourced": "partial"`）、还没有卡的各有几条。
- **分享卡上也有「面试底气」**，调暗，放在计分的几行下面。做 Step 0 之前是锁住的，带一行小字「第二阶段 · 采访后解锁」。第一次体检后，AI 也会用两行说明第二阶段会解锁什么。
- **报告可以存成图片。** 新的 `scripts/report_png.py` 用你已有的 Chrome、Edge 或 Brave，把分享卡（加 `--full` 就是整份报告）存成 PNG，在对话里就能直接看。以前在不运行 JavaScript 的对话窗口和预览窗口里只看得到水印；现在报告文件会说明原因，以及怎么打开。
- 每条 bullet 可以在新的 `claims` 字段里写对应的 Claim ID，完整报告显示在 bullet 下面，分享卡不显示。
- 修复：`report_share.py` 会把证据标注都转成「是 / 否」。
- 示例报告的分数变成 38 和 89（原来 34 和 90）。
- **Claim Card 把三件事分开记。** `status` 仍然决定能不能上简历，新增一个值 `仅面试`：属实，但不写进简历（客户名、保密数字）。新的 `evidence:` 字段记这件事在面试里站不站得住。「数字与口径」表新增「核实」一列，每个数字标 `✓` 或 `待核实`，一个数字没确认，不再卡住整张卡。
- **按真实求职场景放宽。** `evidence:` 记的是面试里你能讲多扎实，不是拿不拿得出合同：`讲得清`（默认，大多数经历在这档）、`有记录`（能说出来源就行）、`有人可证实`、`说不太清`（只有这一档需要处理）。采访时 AI 把卡的要点给你看一眼，你说「对」，这张卡就能用，不用另外复核一轮；你亲口说的数字直接算确认。`需复核` 只留给 AI 从旧材料里摘、你还没亲口说过的事实。
- `check_claims.py` 会拦下标着 `待核实` 的数字和 `仅面试` 的卡。
- **打分判定更一致。** 「动作开头」不再接受 Helped、Assisted、Supported 这类看不出你做了哪部分的弱动词。结构检查放宽：最近两段经历各 2 ~ 5 条，更早的 1 ~ 3 条就够。REPORT 里给结果、数字、动作开头、具体各配了「算 / 不算」的判例，换一个 AI 来标也应该是同一个结果。
- 修复：卡片模板默认是 `Safe to draft`。现在新卡默认 `需复核`，和工作流一直写的一样。

**你需要做什么**：不需要。没有 `evidence:` 和「核实」列的旧卡照常能用，下次复核时补上就行。已经做好的报告，页面上还是原来的分数。`report_score.py` 和改前改后海报对两份报告都用新公式，所以海报比较的仍是同一把尺子。想让旧报告的页面也更新，让 AI 重做一次体检。

## 0.2.0 · 2026-11-19

**新增**
- **简历体检报告。** 给任何一份简历出带分数的可视化报告，可以只看简历，也可以对照 JD。AI 只给每条 bullet 做标注，计数和算分由模板完成，所以不管哪个 AI 来填，分数都一样。见 `docs/REPORT.md` 和 `report/template.html`；`scripts/report_score.py` 在对话里给出同样的分数。一个文件两种视图：完整报告，以及可以截图发出去的分享卡（隐藏姓名、公司和 bullet 原文）。AI 会问你要不要分享版；`scripts/report_share.py` 另存一份删掉所有隐私信息的副本，可以直接当文件发。
- **改前改后海报。** `scripts/report_compare.py` 用两份报告做一张海报：两个分数，每个维度的改前改后。分享卡和海报默认只有分数；你可以加一句话定位、目标方向、关键词标签或亮点，每一项都来自你的 Claim Card，绝不出现公司名。提示词 6。
- **Step 0 采访变短。** 先出体检报告，再给计划：最强的 3 项成果，每项最多 5 个问题，附预计时间。每个问题都带进度条。三种问法：一问一答、一项一张表、直接口述。「跳过」和「先到这」随时有效。进度存在 `evidence/INTAKE.md`。
- **你的规则有了单独的文件。** `docs/MY-DECISIONS.md` 放你自己的规则（从 D-101 编号）。`docs/DECISIONS.md` 只放起步规则，更新时整份替换，所以更新永远不会冲掉你的规则。
- **更新机制。** `VERSION`、这份更新记录，以及提示词 5。
- Claim Card 新增「待补」一节，放采访时跳过的问题。
- 流程图和报告加了图标，水印统一为 RESUME-GATE。报告里的总分和每个维度按分档上色（红、赭、蓝、绿），标题和数字用衬线字体。

**你需要做什么**
- 如果你在 `docs/DECISIONS.md` 里加过或改过规则，要挪到 `docs/MY-DECISIONS.md`。提示词 5 会帮你挪，并告诉你挪了什么。
