# WORKFLOW · 做一版简历

> 每步的「产出」写不出来，就不进下一步。

还没有基线简历？先做 [Step 0](#step-0冷启动)。

## 任务模式

不是每个请求都要走完七步。按本人要做的事选模式；拿不准就按**定制**。

| 模式 | 什么时候 | 步骤 | 给本人看什么 |
|---|---|---|---|
| **快改** | 只改已有版本的几行，并且**没有新 JD**：改一条 bullet 的说法、错别字、缩短 Summary、联系方式 | 读这几行引用的卡。在 Draft 上直接改（已投递的版本是冻结的，先复制，D-010）。对它跑 `check_claims.py`。在它的 Change Log 里记一笔 | 改动前后的这几行，以及检查结果。只报问题，不出完整的 Coverage Report |
| **定制** | 新 JD、新方向，或改动不止几行 | 下面的 S0 到 S7 | S7 要求的全部内容 |
| **定稿** | 本人马上要投递 | 跑 `check_claims.py cv/resumes/<id>.md --finalize`，导出文件、检查排版（见下）、冻结 | 页面截图或本人对排版的确认，以及冻结结果 |

快改做着做着发现动到了某条 claim 的意思、受保护的 claim，或者这一版的投递方向，就转成定制。

**定稿：排版检查。** 导出 PDF 或 DOCX。在 macOS 上跑 `swift scripts/pdf_fill.swift <file.pdf> <目录>`，看它生成的页面图片。在其他电脑上，工具能打开 PDF 的话 AI 自己先看一遍，**并且**要问本人：「请打开 PDF 看一下：页数对不对？最后一页是不是只有零星几行？」本人说没问题，这一步才算完成。`check_claims.py --finalize` 也必须通过：这一版引用的卡有未处理的重大变化，或者还没对照现在的卡检查过，它就不通过（见[事实改了怎么办](#事实改了怎么办)）。然后冻结：`python3 scripts/freeze.py cv/resumes/<id>.md <导出的文件>`。

| 步 | 做什么 | 产出 |
|---|---|---|
| S0 | **保存 JD**：把招聘启事存进 `jobs/<job-id>.md`（复制 `jobs/_TEMPLATE.md`）：原文、在哪里什么时候看到的，以及编号为 R1、R2… 的核心要求，硬性要求标成门槛。后面所有步骤都用这些编号，JD 要的东西就不会悄悄漏掉。每做完一步，在文件的「进度」一节里勾上 | `jobs/<job-id>.md` |
| S1 | **先定位，再选基线**：匹配任何东西之前，先从第一性原理拆解这个岗位：公司为什么招人（这个岗位是为了解决什么问题）、做满一年之后算做得好是什么样、哪些要求是硬门槛（D-016）、哪些只是加分项、招错人会在哪里栽跟头。把答案写在岗位文件的「这个岗位真正要解决什么」一栏，猜测的部分要标出来。这些答案只用来决定先讲什么、去哪里找证据，不是关于本人的事实，也绝不写进简历。如果这个岗位离你已有的类型比较远，写 2–3 个一句话的定位方案（切入角度、最强的证据、主要缺口），并推荐一个，然后停下来让本人选定，再做 S2；如果很接近，一句话就够，直接往下做。然后按匹配程度选基线：定位和选定的方案有多接近、它的 claim 已经覆盖了多少 JD 要求、是不是 Approved、新不新。基线提供的是事实和已批准措辞，不是叙事：选定的定位可以重新排序或重新组织它（D-018）。署名 / 联系方式变体按类型选 | 「定位：…；类型 X，起点 = …」 |
| S2 | **Evidence Retrieval Gate**：过一遍**每一张** Claim Card，不只是听起来相关的那些：一个标题可能藏着 JD 想要的能力（有能力切面的话看切面）。卡片超过 15 张时，先跑 `python3 scripts/list_claims.py`（每张卡一行），再打开所有受保护的卡，以及一句话、职位或能力切面和岗位沾边的卡读全文；不超过 15 张就全读。在 Change Log 里填证据表：用上的卡每张一行，写明用在哪。没用的卡可以按原因合成一行（「低：C-012、C-015，领域无关」），表格不会太长；受保护的卡、明显和岗位相关的卡，即使没用也单独一行写原因。证据表漏了哪张卡，`check_claims.py` 会提醒。然后问一次：有没有哪张没用上的卡，比简历里已有的某条更适合这个岗位？有就换进来，或者写明为什么不换。换不出明显的提升就停（D-019） | Change Log 里的证据表 |
| S3 | **JD 映射**：要求 R1、R2… 每条归入五类之一：**直接** · **可迁移或组合**（另一个场景里的同类能力，或几段经历各证明一部分）· **还没找到**（先过[追问清单](#追问清单)，D-014，再[在卡片之外找](#在卡片之外找)，D-021；标着「待核实」的数字也归这里）· **可补足**（真实缺口，但一个小项目或课程就能补上）· **硬缺口**（包括不满足的资格门槛）。只有「硬缺口」意味着不写。追问后仍然没有证据的，不硬写。公司名、职位名、工作地点、薪资福利不是要求，永远不算缺口。简历有没有用上 JD 的关键词，和它有没有证明 JD 要的价值，是两回事，分开看（D-011） | Coverage Report 里的五类映射 |
| S4 | **Delta**：复制 `cv/resumes/` 里的基线文件，只改需要改的：定位句、Summary、bullet 顺序、关键词。不重写已批准的部分。如果 `check_claims.py` 提示某一行复制自一个在卡片改动之前批准的基线，就按现在的卡重写这一行。**写一行（新写或改写）：** 先列出卡上确认的事实，挑出最能证明这个岗位所需的那几条，再为这个岗位写这一行。卡上的已批准措辞只是参考：只有它本来就是最强且准确的说法时才原样保留。卡上没有的事实、数字、职位一律不加；一行里的数字个数不设上限，留下能证明这一行要点的，砍掉的数字在 Change Log 里记一笔 | 新版本草稿 |
| S5 | **Change Log**：每处改动编号写成一条提案：Before / After 加引号、依据（卡片编号）、状态 `待定`。附 JD Coverage Report 和检查范围。本人看过各行之后，跑 `python3 scripts/check_claims.py cv/changelogs/<id>.md --record all`。每一行单独记录（只记第 2 行用 `--record P2`），所以之后卡片再改，基于旧卡的提案会显示过期，从没检查过的也不会被当作有效提案。「位置」栏写清楚是哪一节或哪段经历（「Summary」「Experience」）：脚本会到那里去找 Before 原文 | `cv/changelogs/<id>.md` |
| S6 | **AI 自审**：按 [REVIEW-CHECKLIST](REVIEW-CHECKLIST.md) 的 A、B 两节逐项过；跑 `python3 scripts/validate_evidence.py` 和 `python3 scripts/check_claims.py cv/resumes/<id>.md`（都必须通过）。导出 PDF 和排版检查留到定稿 | 自审改动表、检查结果 |
| S7 | **人工审核**：把全文 + 改动对照交给本人，把整份简历用 markdown 贴在聊天里，改动直接标在文字里（旧写法划掉，新写法加粗），整体只问一次（这一次也就是 S5 那些行的确认，不要再单独问一轮），再列出还没定的几个判断点。不要一条一条地问，不要只发截图或链接，说到改动时用大白话，不要只报编号。本人仍然可以拒绝任何一处改动：你根据他的回答给每行标 `接受` 或 `拒绝`，被拒绝的文字要从简历里删掉。拒绝一种措辞是措辞偏好，不是事实改了：除非本人说事实错了，否则不动卡。本人说通过才改状态为 `Approved`。然后跑 `python3 scripts/check_claims.py cv/resumes/<id>.md --record all` | 本人批准记录 |

投递之前先**定稿**（见[任务模式](#任务模式)）：导出、检查排版、冻结。`python3 scripts/freeze.py cv/resumes/<id>.md <导出的.pdf>` 会把两个文件的 SHA-256 记进 `cv/frozen.txt`，之后冻结的简历被改动，`check_claims.py` 就会报错。版本改状态为 `Sent`，`cv/CV-INDEX.md` 里记下是哪个岗位用了它。

**之后接着做。** `jobs/<job-id>.md` 的「进度」一节写着哪些步骤做完了、哪些在等本人。它只是线索，不是凭据：用之前先对照文件（Change Log、简历的状态）核实，只有本人亲口说过的才算批准。

**只认一份正本。** `cv/resumes/` 里 Approved 的那一版才算数。放在别的工具里的副本（简历生成器、招聘网站），由本人自己保持一致；交给本人时要说明它来自哪一版。导出的文件仍然要做排版检查，并且要和 Approved 的那一版一致。

## Step 0：冷启动

只做一次，在第一个岗位之前。它带你从「我有一份旧简历」走到「我有一份已批准的基线」。

| 步 | 做什么 | 产出 |
|---|---|---|
| 0a | **收集原始材料**：现在的简历、LinkedIn 文字、过往的绩效评语，任何含事实的东西。放进 `evidence/sources/`。这个目录已被 git 忽略，不会被提交 | `evidence/sources/` 里的文件 |
| 0b | **体检报告。** 用 [PROMPTS](PROMPTS.md) 里的提示词 1。AI 读简历，按 [REPORT](REPORT.md) 的标准数数，填进 `report/template.html`。采访之前就先拿到一份带分数的可视化报告：哪里强、哪里含糊、最该先改的 5 处。然后问你要不要一份可以分享的版本 | `reports/<日期>-checkup.html` 和它的卡片图、对话里的三行摘要，要的话还有 `-share.html` |
| 0c | **采访计划。** AI 挑出**最强的 3 项**成果（够出第一份基线，其余以后再补），读完材料后只列每项还缺什么，把计划写进 `evidence/INTAKE.md`：一共几个问题、大约多久。本人选一种问法（见下文） | `evidence/INTAKE.md` |
| 0d | **采访并写卡。** 用提示词 2。每个问题前都带一行进度。任何问题都可以跳过，随时可以停：没答的记在卡上「待补」，不再追问。每做完一项，AI 把卡的要点（做了什么、数字、不能说的，以及一句参考写法）给本人看一眼，本人说「对」或改几处，这张卡就是 `Safe to draft`，不用另外再复核一轮。「对」确认的是事实，不是最终的 bullet 文字；有风险的说法（见「什么算有风险」）除外 | `evidence/claims/` 里的 Claim Card，`INTAKE.md` 同步更新 |
| 0d+ | **填好 `evidence/profile.md`**：任职（职位、公司、开始、结束）和教育背景，从现有简历里摘出来，由本人确认。`check_claims.py` 会拿每个职位标题和教育那一行来对照它 | `evidence/profile.md` |
| 0e | **起草第一份基线**，只用 `Safe to draft` 的卡。复制 `cv/resumes/_TEMPLATE.md`，每条 bullet 都标上 Claim ID | `cv/resumes/<id>.md` |
| 0f | **审核并批准**，流程同 S6、S7。把它登记进 `cv/CV-INDEX.md`，作为该类型的起点。然后 AI 会提议再跑一次体检，做一张改前改后海报（提示词 6） | 一份 Approved 的基线；想要的话，一张海报 |

`cv/CV-INDEX.md` 里至少有一个 Approved 的起点，就算完成。之后每个新岗位都走 S1 到 S7。想补卡随时用提示词 2；再跑一次体检（提示词 1），能看到分数的变化。

### 让采访短一点

采访是 Step 0 最耗时的部分，所以 AI 要把它压小，并且随时说清楚进度。

- **材料里已有的不再问。** 旧简历写了「伙伴从 12 家扩到 40 家」，就用一个是 / 否问题确认，不要让本人再讲一遍。
- **每项成果最多问 5 个问题。** 问完还缺的，记在卡上「待补」。
- **三种问法，本人在 0c 选一种：**
  - *一问一答*：一次一个问题。最慢，最轻松。
  - *一项一张表*：这一项的问题一次发完，本人一次回复。
  - *直接口述*：本人一大段随便讲，AI 自己拆出事实，只问剩下的。
- **每个问题前带一行进度**，格式：

  `▓▓▓▓▓▓░░░░░░░░░ 6/15 · 第 2/3 项 · 本项第 1/5 问`

- **「跳过」和「先到这」永远有效。** 说「先到这」时，保存 `evidence/INTAKE.md`，并说明下次从哪接着做。

## 拿到面试之后：追问卡

简历上每一条都可能被追问：「这个数怎么算的？」「哪部分是你做的？」「这都是你带来的吗？」答案其实早就在 Claim Card 上：口径、归因、不能说的因果、出处。追问卡就是把它们按面试的顺序重新排一遍。

- **什么时候做**：拿到面试邀约之后，针对投出去的那一版简历。用提示词 7，或者 `/prep`。先用已经存好的东西：`jobs/<job ID>.md` 里存的招聘启事，和 `cv/` 里这个岗位的简历。只有其中一份找不到时，才向本人要。
- **产出**：`interview/<岗位编号>.md`，照 [`interview/_TEMPLATE.md`](../interview/_TEMPLATE.md) 的格式。示例：[`examples/jordan-lee/interview/ACME-01.md`](../examples/jordan-lee/interview/ACME-01.md)。

**追问从卡上来，不靠猜：**

| 卡上的 | 变成的追问 |
|---|---|
| 数字与口径 | 「这个数怎么算的？时间多长？基数是多少？」 |
| 归因 | 「哪部分是你做的？团队多大？」 |
| 不能说的因果 | 「这个增长都是你带来的吗？」：如实划清边界 |
| 禁止改写 | 面试官顺着说大：「所以你带来了 200 万营收？」：当场纠正，比被背调发现好得多 |
| 出处 | 「有数据支持吗？」：说得出来源就行，不用拿出来 |
| 备注 | 卡上已经写好的面试要点 |
| Coverage Report 里「部分」「无」 | JD 要但证据不够的能力：怎么用相邻经历诚实地回答 |

**规矩：**
- 回答只用卡上的事实。卡上没有、但大概率会被问的，列进「面试前要补」，问本人，不编。
- 每条 bullet 最多 3 个追问，挑最可能被问的。顺序和简历一致，最强的在前。
- 最上面先列风险：`说不太清`、`需复核`、`待核实`，以及踩到「什么算有风险」的说法。
- `仅面试` 的卡放进「可以主动讲的素材」：简历上没写，面试里讲出来是加分项。
- 按现在的卡来写，不照抄旧的追问卡或聊天内容。写完跑 `python3 scripts/check_claims.py interview/<岗位编号>.md --record all`。如果投出去的版本早于某张卡的改动，检查会提示：已投递的文件保持原样，把差别写进「先看这里：风险」，按现在的卡准备。

### 已审核的答案

本人批准过的回答（「为什么离职？」「讲一次没做成的上线」）可以复用，但只在适用的范围里用，而且只在它引用的卡没改过的时候用。

- **放哪里**：`interview/answers/<A-编号>.md`，照 [`interview/answers/_TEMPLATE.md`](../interview/answers/_TEMPLATE.md) 的格式。每个事实标上卡片编号。
- **适用范围**：`reusable`（任何岗位都能用）、`employer: <公司名>`（要和岗位文件里 `company:` 写的公司名完全一致；大小写和标点不计，但「Harbor」匹配不了「Harbor Analytics」）、`job: <岗位编号>`（为某一次投递写的）。超出范围的答案不复用。本人的批准覆盖问题、适用范围和文件里除「备注」以外的全部内容，所以改了其中任何一项都要重新确认。用过几次之类的记录写在「备注」里，不会触发重新确认。
- **本人批准后记录**：`python3 scripts/check_claims.py interview/answers/<A-编号>.md --record all`。
- **复用之前**：`python3 scripts/list_claims.py --answers <岗位编号>` 会列出适用的答案，以及每条能否复用。只有「能」才是照用：它引用了卡，没有卡不存在或改过，对照过卡，本人也批准了。其他情况（没批准、没检查、没引用卡、卡不存在、卡改过）都按现在的卡重写，再确认一次。

## 事实改了怎么办

目标：本人只纠正一次，后面的每一步都知道。用过旧事实的地方不会在没人注意的情况下被继续使用，无关的内容也不需要重新审核（D-020）。

**1. 是纠正，还是换说法？** 纠正会改变什么是真的、什么能说：发生了什么、一个数字或它的口径、谁做了哪部分、状态、不能怎么说。「那 $200K 不是市场预算，是我谈下来的赞助」是纠正。「这条写得更有力一点」是换说法：改简历，不改卡。分不清就问一个问题。

**2. 先改卡**，在同一轮里改，并用一句话复述改了什么。保留这项成果最强的真实版本：纠正是把说法收窄，不是把成果删掉（D-015）。如果纠正让出处变弱了（「那份报告已经没有了，是凭记忆」），除了出处那一行，也要把卡的证据强度或状态调低：这样引用它的文件才会知道这是重大变化。

**3. 看影响到哪些文件**：`python3 scripts/list_claims.py --used-by C-xxx`。告诉本人哪些文件引用了这张卡、各自要不要复核。不要自己去改已批准或已投递的文件。

**4. 从这以后以卡为准。** 这次聊天里之前说过的、旧简历里、追问卡里和卡不一致的内容都作废。纠正很多之后，建议开一个新会话。

**检查是怎么知道的。** `check_claims.py --record` 把每张卡各区块的指纹，以及引用它的那几行，记进 `cv/reviewed.txt`。每次运行时，脚本根据这些现场算出每个文件的状态，不往简历里写任何东西：

| 状态 | 意思 | 会怎样 |
|---|---|---|
| 最新 | 引用的每张卡都和批准时一致 | 什么都不提示 |
| 需要复核 | 批准之后，引用的某张卡改过 | WARN，指出是哪张卡、改了哪些区块。`--finalize` 时，重大变化算错误；卡有任何变化、同时引用它的行在批准后也改过，同样算错误 |
| 改动前已投递 | 这一版投出去之后，卡才改 | 只给提示。已投递的文件保持原样；提醒落在追问卡上 |
| 卡片不存在 | 引用了一个不存在、这里也从没记录过的卡片 ID：写错了，或者是 0.7.0 之前就删掉的卡。（记录之后才删的卡显示为「需要复核：卡片已删除」） | `--used-by` 和 `--health` 会列出来。简历里出现未知 ID，`check_claims.py` 本来就会报错 |
| 未检查 | 还没有记录（0.7.0 之前做的版本，或记录不完整），或者记录之后这几行被改过 | 只汇总成一行。`--finalize` 时算错误，直到本人确认、你记录为止 |

**「最新」不等于「已批准」。** 这些状态只说明那几行和卡是否还一致。一个版本有没有被本人批准，看的是它的状态（Draft / Approved / Sent），只有本人能改。「最新」的 Draft 仍然是草稿；已审核的答案要同时是「最新」和 Approved 才能复用。

从基线复制出来的草稿，凡是原样复制自一个在卡片改动之前批准的基线的行，也会各给一条 WARN：旧说法就是这样混进新版本的。

| 重大（可能改变事实） | 一般（通常是措辞） |
|---|---|
| 事实（以及卡片标题）、数字和核实列、归因、状态 / 证据 / 职位 / 时间、禁止改写，以及改变了这份文件岗位类型必须保留什么的 protected / keep-for | 已批准措辞、能力切面、出处、模板里没有的栏目。「备注」和「待补」永远不算 |

空格、段落里的折行、加粗、横线写法和 1,234 这种千分位逗号不算改动。新起一条 bullet 或一行表格算；`1.234`、`1 234` 和小数逗号也算，因为不同地区写法含义不同。约定是：数字之间的逗号后面正好跟三位数字，就当作千分位，所以 `€2,100` 和 `€2100` 是同一个数。卡上的小数一律用小数点（`€2.1K`），不用逗号；其余每个字符都算，所以 `$2.1M` → `$21M` 是改动，`$200,000` → `$200000` 不是。

**复核。** 只把引用这张改过的卡的那几行给本人看，旁边放上卡现在的内容。还成立的话，只对这张卡跑 `--record C-xxx`；这一版其余部分的批准不受影响。不成立的话，做一个新版本（已批准或已投递的文件不在原地改）。

**需要复核不等于发现了错误。** 它只是说，还没人对照改过的卡看过这几行。

## Claim 状态

| 状态 | 含义 | AI 能在简历里用吗？ |
|---|---|---|
| `Safe to draft` | 你读过这张卡，确认了事实和措辞限制 | 能 |
| `需复核` | 还没确认，或者有风险（见下文「什么算有风险」） | 不能。AI 只能就它向你提问 |
| `仅面试` | 属实，但不适合写进简历：客户名、保密数字、只能当面讲的细节 | 不能。面试准备时可以用 |
| `已停用` | 过时、有误，或你不想再主张 | 不能 |

状态回答的是「能不能写进简历」。另外两件事分开记：

- **单个数字有没有确认**：卡上「数字与口径」表的「核实」一列。本人在采访里亲口说的数字直接是 `✓`；本人说「大概」、或者 AI 从旧材料里摘出来还没问过本人的，才是 `待核实`，这些不能上简历。
- **面试里站不站得住**：卡上的 `evidence:`。大多数经历拿不出合同或报表，面试靠的是你讲得多扎实，所以默认档 `讲得清` 就够用。只有 `说不太清` 需要处理：面试前补细节，或者简历上写保守一点。

| `evidence:` | 意思 |
|---|---|
| `讲得清` | 来龙去脉、数字怎么算的、哪部分是你做的，你都能讲清楚。大多数经历在这一档，面试够用 |
| `有记录` | 另外还有文档、报表、邮件。不需要拿得出来，能说出来源就行 |
| `有人可证实` | 前上司、客户、合作方，或公开报道能证实 |
| `说不太清` | 只记得大概，细节或数字讲不清。面试被追问容易卡住 |

`需复核` 留给还没真正确认、或者有风险的说法，见下一节。

### 什么算有风险

采访里本人说「对」，卡就能用，除非它踩到下面任何一条。踩到了，卡先留 `需复核`：

| 风险 | 例子 |
|---|---|
| **不是本人亲口说的** | AI 从旧简历、LinkedIn、文档里摘出来，本人还没在采访里说过 |
| **本人自己不确定** | 「大概」「好像」「差不多是」 |
| **说法很大** | 大金额、「第一」「首个」「唯一」、成倍增长、明显超出这个职级通常能负责的范围 |
| **把集体的结果算在自己头上** | 公司融资、团队营收、整个市场的增长，写得像是本人带来的 |
| **面试大概率会要证据** | 具体金额和客户名、能公开查到的数字（融资额、用户量、排名）、奖项、晋升、背景调查能核到的事 |
| **和别处对不上** | 旧简历、LinkedIn、另一张卡写的数字或头衔不一样 |

**怎么处理：** 这不是说本人在夸大，只是这句话在面试里最容易被追问。AI 指出踩到哪一条，问一个问题：这个数怎么算的？依据是什么？你负责的是哪部分？本人讲清楚了，把依据写进卡，改成 `Safe to draft`。讲不清，就换一个保守、站得住的写法（D-015），或者先留着 `需复核`。

## 关键原则

**事实只朝一个方向流。** 原始材料 → Claim Card → 已批准措辞 → 简历版本。简历从基线继承措辞和结构，但不继承事实：每一行仍然要靠 Claim Card 站住。否则某份旧简历里的一个错误，会被批准、被复制，然后带进之后的每一个版本。

**基线 + Delta，不从空白开始。** 新岗位继承匹配度最高的已批准版本，通常是同类里最新的那份。这样已确认的事实和已定的结构不会丢。如果同类没有基线，从最近的相邻类型派生，并在 Change Log 里说明。

**Evidence Gate 要可检查。** 「我读了证据库」不算数，要列出具体 Claim ID。列不出来，说明没读。

**先挖，再过滤。** 「没证据不写」「计划不等于成果」这类规则，都是在追问之后才执行。候选人常常把做过的事说得很简略：一份「没落地的提案」里可能有一部分被采用了，一个「协调岗」可能设计过商业方案。先用追问清单把价值挖出来，再判断能写到什么程度（D-014）。

**没证据就不写。** JD 要的能力，在卡片之外也找过之后（D-021）证据库里仍然没有，写进 Coverage Report 的「无」一栏，由本人决定是补证据、面试时讲，还是放弃这个岗位。

**不删强成果，除非有理由。** 删一条已有的强 bullet 要过三关：相关性（对这个岗位没用）、真实性（有疑问）、篇幅（排不下），并在 Change Log 写明。标了 `protected: true` 的 claim，未经本人批准不能写弱。卡上如果写了 `keep-for` 类型，这些类型的简历里必须保留它，其他类型可以不放；没写 `keep-for` 就处处保留。

**两种错误。** 写了证据撑不住的内容是一种（多写）；证据撑得住、岗位也看重的内容却没写，是另一种（漏写）。检查脚本拦的是前一种；S2 的证据表是为后一种准备的（D-019）。

**排版服从内容，不反过来。** 页数不对时，先改内容（删弱 bullet、精简长句），再动字号 / 行距 / 边距。不为了凑页数加没有证据的内容。

## 追问清单

写 Claim Card、做 JD 映射、标「没有证据」之前，至少问过这几个问题：

1. 这件事如果你不做，会不会发生？哪一部分是你个人做的，哪一部分是团队？
2. 你职位名称之外，实际还负责过什么？
3. 你参与过哪些和钱有关的决定：预算、报价、合同、赞助？
4. 这份提案或计划里，有没有哪一部分后来被采用或执行了？
5. 这两件事之间有没有关系？是直接导致、间接支持，还是各自独立？
6. 这个数字量的是什么：单位、时间窗口、累计还是单个、实际还是潜在？
7. 之前有没有哪种写法被你纠正过？（纠正过的弱化说法最容易回来）

**答案马上写回去。** 本人回答了关于某一条 bullet 的问题，如果是事实，就在同一轮里改它的卡，并把改好的那一行给本人看。简历正文只能直接改还在草稿（Draft）阶段的那一版；已批准（Approved）的版本，把改动作为建议提出来；已投出（Sent）的版本保持投出时的样子（D-020）。只是措辞偏好的，只改简历，绝不改卡。不要等本人来提醒。

## 在卡片之外找

确认过的事实都在卡片里。但一件真实的成果，可能只存在于本人自己的资料里（项目复盘、绩效评估、访谈记录），还没有卡片；这时说「没有证据」是错的（D-021）。下面是怎么找，又不用每次把所有资料读一遍。

### 什么时候找

先从卡片开始，要看卡片正文，不能只看一句话清单。只在下面这些情况才往外找：

| 卡片对这条要求的覆盖情况 | 要往外找吗？ |
|---|---|
| 有强而直接的证据 | 不用，到此为止 |
| 只有弱的或可迁移的证据 | 要，如果它是门槛或核心能力 |
| 有卡，但缺岗位需要的结果、规模或归因 | 先问本人（[追问清单](#追问清单)，D-014），再去资料里找 |
| 门槛要求，完全没有证据 | 一定要 |
| 加分项 | 只对多看一眼可能改变结果的那几条 |

力度跟着重要性走，不设固定个数：每条门槛都要找，不能因为没花力气就写成「没有证据」。没有余力深入的，写「尚未深入检索」，不写「没有证据」。

### 按什么顺序找

1. 卡片，所有状态。`需复核` 的卡或「待补」里可能已经有了；`仅面试` 的卡不上简历；`已停用` 的卡永远不能当支持材料：同一件事又冒出来，仍然是停用，除非本人把它请回来。
2. `evidence/profile.md` 和 `interview/answers/` 里已审核的答案。
3. `evidence/sources/` 里的文件，以及本人自己的规则指到的地方（比如「也看我笔记软件里的某页」）。`python3 scripts/list_claims.py --sources` 列出文件和指纹，并标出哪些是新的、改过的、已跳过的。
4. 旧简历和追问卡：只是线索，不是证明（AGENTS）。

读过的文件仍然是可以再找的地方：一份长文档，一遍很难榨干。「读过」「读过之后变了」「改名」「已跳过」描述的是文件，不是里面的证据。

### 怎么读一份资料

- 先在本地定位相关部分（搜索、目录、页码范围），只把那一部分交给模型。工具没法只读文件的一部分时（扫描件、图片、外部连接），如实说明，让本人选：给摘录、允许读整份，或者跳过。
- **已跳过**的资料，是本人写在 `evidence/INTAKE.md`「跳过的资料」里的：一个文件，或者末尾带 `/` 的文件夹。不要打开、搜索或引用它，更不能交给模型。脚本也不会打开它。对其他文件，脚本只在本机算指纹，不读文字，也不会把任何内容发到别处。**跳过是对路径的限制，不是对内容的锁**：被跳过的文件改了名、或者被挪出它所在的跳过文件夹，看起来就是一个新文件，所以文件可能会挪动时，请跳过整个文件夹。比较路径时不分大小写，也不分 Unicode 写法；跳过行的文件名或原因里有 `|` 时没法可靠解析，会像读不了的 INTAKE 一样让列表停下：请给文件改名，或者改写原因。
- 链接一律不跟随：指向文件的链接、路径中间某个文件夹是链接、或者资料文件夹本身就是链接，列表里都会点名，但不会读。脚本进不去的文件夹会标成不可访问：要报告这一点，而不是说「没有文件」。如果 `--sources` 说 `evidence/INTAKE.md` 里的跳过规则读不了，就停下：它什么都不会列，文件修好之前，不能读任何原始资料。
- 云同步文件夹：`--sources` 能识别 iCloud 的占位文件，并且不会打开它们。它只识别 iCloud。用其他同步工具时，算指纹可能会触发下载，用 `--sources --no-hash` 只列文件名和大小。资料文件夹很大时，先用 `--no-hash`，再只给你挑中的文件算指纹。指纹是 SHA-256 的前 16 位十六进制：足够判断文件变没变，不能证明别的。
- 读一份资料之前，记下它的指纹（`python3 scripts/list_claims.py --fingerprint <文件>`）。把发现写进卡之前再跑一次；要改的那张卡，也在读它之前和写入之前各算一次指纹。只要有一个变了，就重新看受影响的部分，不要照旧的读法写。这能发现你工作期间被别人改过的文件，但它不是锁。
- 真的读过之后，在 `evidence/INTAKE.md` 的「来源记录」里加一行：路径、指纹、日期。没读过的文件不要登记。为哪个岗位、哪条要求找过，写在那个岗位的 Coverage Report 里，不写进 INTAKE。

### 找到之后怎么办

- 和已有的卡是同一件事（任何状态，包括 `已停用`），或者是本人已经拒绝过的事（见下）：更新那张卡，或者不动。不要新建一个 ID 绕过去。
- 是新的：写一张状态为 `需复核` 的卡，Source 写文件名，加页码、章节或脱敏摘录，然后问本人一个问题。
- 给本人已经确认的卡补充新材料：这张卡的 `Safe to draft` 不覆盖新内容。新数字要标 `待核实`；新的成果、贡献或归因，先作为提案等本人确认（或者把这张卡改回 `需复核`），确认之前，不能让旧的确认带着新内容过关。
- 谁要确认什么：

| 事实来自 | 要和本人确认吗？ |
|---|---|
| AI 从旧简历、文档或笔记里找到的 | 要，本人说「对」之前都要 |
| AI 自己推出来的：谁导致了什么、哪部分是谁的 | 要 |
| 本人在这次对话里说的 | 不用：本人自己的陈述就算确认（D-017） |
| 本人的纠正 | 不用：直接改卡（D-020） |
| 本人说自己不确定的 | 要 |
| 本人明确说卡里标着「待核实」的数字是对的，没有含糊（没说「大概」「我觉得」） | 不用：立刻改卡。把「核实」打上 ✓，去掉残留的「待核实」字样，写上日期和本人说的出处，然后继续往下做 |
| 本人只说了这个数字在哪里能查到 | 还不算：知道出处不等于确认了数字。先去读那份资料（D-021），和卡片对一下，说出你找到了什么，问一句是或不是。本人已经确认过的，绝不再问。只有卡里完全没有这个数字的出处，或新资料与它矛盾时，才问数字 |

- **资料和卡不一致时：**

| 是什么情况 | 怎么办 |
|---|---|
| 旧资料和本人后来纠正过的事实矛盾 | 以卡为准，不再问 |
| 新资料可能推翻这张卡 | 标出冲突（见下）并询问 |
| 本人当面纠正事实 | 马上办（D-020） |
| 同一件事换了说法 | 不算冲突 |
| 金额、归属、单位或时间范围不同 | 标出来，发送前必须解决 |

标冲突用现有的办法：有争议的是某个数字，就在它的「核实」一栏写 `待核实`；有争议的是整项成果或者谁做的，就把卡改成 `需复核`（只有一部分有疑问时，把卡拆开）。原因写在卡的「待补」里。之后 `check_claims.py` 会拦下用到它的每一行，`--finalize` 会拦下引用它的版本；没有引用它的版本不受影响。`protected-ok` 只表示本人批准省略一条受保护的成果，绝不能用来放行一条卡片有争议的成果。

### 不重复追问

本人对你找到的某件事说了不，就在 `evidence/INTAKE.md` 的「已否定的事实」里加一行：是什么、为什么（错的 · 不是我的 · 对，但不适合写进简历）、日期。如果已经有对应的卡，改卡就行（D-020）。「这个岗位用不上」不要记（那属于这个岗位的证据表），「现在没时间」也不要记（卡保持 `需复核`）。问本人之前，先看这份清单。

### 报告怎么写

在 Coverage Report 里分开写两件事：证据是什么（已确认、等本人确认、有冲突、没找到），以及找到了多深（卡片、连资料也看了、部分、不可访问、尚未深入、等本人回答）。「没有证据」的意思是卡片和资料都查过了，确实没有；有什么没能查，就说没能查。「检查范围」里列出实际读过的文件。报告是你自己对这次查找的说明：里面没有任何东西能证明它。

## Coverage Report 格式

```markdown
| # | JD 要求 | 门槛 | 类别 | 证据 | 检查到哪 | 下一步 |
|---|---|---|---|---|---|---|
| R1 | 要求 A | 是 | 直接 | C-003 | 卡片 | 无需 |
| R2 | 要求 B | | 可迁移或组合 | C-007（不是同类场景）+ C-002 | 卡片 | 先讲可迁移的能力；准备好说明场景有何不同 |
| R3 | 要求 C | | 还没找到 | 无 | 卡片和资料；有一份资料不可访问 | 先追问，并请本人提供那份资料的摘录，可能挖出证据 |
| R4 | 要求 D | | 可补足 | 无 | 卡片和资料 | 一个小项目就能补上，由你决定 |
| R5 | 要求 E | 是 | 硬缺口 | 无 | 卡片和资料 | 不写。面试时回答，或放弃这个岗位 |

**检查到哪**写你找到了多深：卡片 · 卡片和资料 · 部分（写明缺什么）· 不可访问 · 尚未深入检索 · 等本人回答。证据在等本人确认，或者和某份资料有冲突，就写在证据或下一步里。资料读不了的要求，写成「还没找到」并在「检查到哪」里说明，绝不写成「硬缺口」。

**检查范围**：已查 …；没查 …（原因）；读过的文件：…
```

岗位匹配报告里，「直接」记为 `direct`，「可迁移或组合」记为 `partial`，其余三类记为 `none`。

## 新类型什么时候成立

三条都满足才在 `CV-INDEX` 里新开类型，否则算已有类型里的岗位版：
